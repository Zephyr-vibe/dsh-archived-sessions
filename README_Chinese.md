# dsh-archived-sessions（归档会话管理）

一个 DSH Web 插件：在「设置」中提供**会话管理**，统一管理本机上的所有对话。

> **English version: see [README.md](./README.md).**

> **本分支（`fix/security-contract-review-fixes`）：一次安全契约评审修复**——`delete-file` 强制 `sessionId` 产出归属校验，删除统一走 `locate()+rm` 围栏路径，磁盘占用改官方 API，并修掉客户端批量操作/选区的边界 bug。下列功能正文与主分支 v0.1.2 一致，此处不重复。

## 本分支的具体变动（相对主分支 v0.1.2，提交 `6c9d3a2`）

- **服务端安全性加固**
  - `delete-file` 的 `sessionId` 改为**必填**：路由层与 `deleteFile` 内部双保险，缺失即 400 拒绝（杜绝仅靠工作区围栏通过回环 API 删除工作区内任意文件的越权路径）；并校验长度上限（>200 拒绝）。
  - 删除路径统一走官方 `locate(meta)` → `dirname` 得会话专属目录 → 递归 `rm`，去掉按字符串入参的 `persistence.remove`（jsonl 后端并不存在该原语）；围栏校验保留：目录必须严格位于会话根目录内，递归 `rm` 永不指向整库或更上层。
  - 删除无用的 `agentLoop.disposeAgent` 死分支（根 context 拿不到创建者持有的 `AgentHandle.dispose`），与官方「无法 dispose 时跳过并删除」对齐。
- **磁盘占用（M1）**：jsonl 后端没有 `artifactInfo` 原语，改用 `locate()` 定位日志文件后 `stat` 字节数作为占用空间；未来后端提供 `artifactInfo` 时自动切换。
- **客户端前端（H2/H3/H4）**
  - 批量操作部分失败不再整体中断：成功项移出选区/详情缓存，失败项保留供精确重试，并给出「成功 N / 失败 M」提示。
  - 搜索过滤变化时把选中项裁剪到当前可见子集，避免「全选→搜索收窄→误操作只作用于可见子集」的语义分裂。
  - 收起详情即清错误、加载中的行不再误显其它行的旧错误。

## 功能

- **双标签页**：**所有对话**（未归档）与**归档会话**
- **视图切换**：**单列表**或**按工作区分组**（无工作区归属的会话兜底归入「未分组」）
- 按标题 + 相对时间浏览对话，最近的排在最前
- 勾选 / 拖动批量勾选 / 全选 / 批量**归档**（记录保留）/ 批量**删除**（永久删除，带确认弹窗）
- 归档页支持**移出归档**（回到所有对话）
- **打开记录文件夹**按钮：在系统文件管理器中打开所选会话的记录目录，跨平台（`explorer` / `open` / `xdg-open`）
- 每行可展开详情（默认收起）：占用空间、最后更新、产出/下载文件、父会话与子会话（分叉）
- **子代理会话**嵌套显示在父会话下方（缩进 + 「子代理」徽标）；父会话被删除或缺失时自动浮出为顶层行
- **删除父会话不会级联**：子代理、分叉、下载/产出文件均保留，除非你显式勾选它们——避免误删
- 当前打开的会话显示「当前会话」徽标，且**不可删除**

## 安装

### 方式一：直接 tarball 安装

```sh
dsh plugin --profile web add https://codeload.github.com/Zephyr-vibe/dsh-archived-sessions/tar.gz/refs/heads/main
```

如果 pnpm 拦截构建脚本，在命令末尾加 `--ignore-scripts`：

```sh
dsh plugin --profile web add https://codeload.github.com/Zephyr-vibe/dsh-archived-sessions/tar.gz/refs/heads/main --ignore-scripts
```

### 方式二：让 agent 安装

告诉你的 DSH agent：

```text
帮我把这个项目安装为插件：https://github.com/Zephyr-vibe/dsh-archived-sessions
```

agent 会下载项目、放入 profile 的 `node_modules` 并注册到 `dsh.profile.bundles`。

安装后重启 web 端，即可在「设置」中看到「会话管理」入口。

## 兼容性（零配置）

零配置：无需任何设置，纯净 Harness 开箱即用。

- **零配置**：会话记录目录自动从官方 DSH 布局推导（`$DSH_HOME/sessions/<project-key>/<session-id>/`），未修改的 Harness 开箱即用——无需打核心补丁。
- **归档 / 移出归档**：在纯净 Harness 上可用，使用官方 `archiveSession` 所依赖的同一套注册表状态原语。
- **删除**：插件分离工作区记账、移除归档集条目，并通过其物理位置（由 `sessionPersistence.locate` 解析、经围栏校验确保在会话根目录内）删除会话目录。删除刻意**不级联**：子代理、分叉与文件除非显式勾选，否则不受影响。正在运行的会话以友好信息拒绝（409）；纯净 Harness 上已打开但空闲的会话需先切换或重启（与官方侧边栏删除相同的限制，因为没有公开的 "dispose agent" API）。
- **磁盘占用**：在详情面板中展示，由会话存储的日志文件通过 `sessionPersistence.locate` + `stat` 计算（未来后端提供 `artifactInfo` 时自动使用）。
- **打开记录文件夹**：用系统文件管理器打开目录（`explorer` / `open` / `xdg-open`），跨平台。
- **仅回环绑定的 API**：插件 JSON API 只信任回环请求（127.0.0.1 / localhost / ::1）。用 `--host 0.0.0.0` 或局域网地址启动 web 端会使「会话管理」不可用（所有请求返回 403）。
- **删除当前会话**：UI 禁止删除当前打开的会话；DSH host 端无公开的「当前会话」API，因此接口本身无法拒绝。任何可访问本机回环 API 的本地进程仍可直接删除当前会话——与官方删除接口行为一致；运行中会话的 409 保护仍然生效。
- **归档 / 移出归档并发**：插件对自身归档集变更做串行化，删除会清理孤儿归档条目；但插件队列与核心 `archiveSession` 队列在极端并发（同一毫秒内归档与取消归档/删除交错）下仍可能丢失一次更新，刷新后 UI 自动恢复。
- 仅使用官方公开 API（`workspaceRegistry`、`sessionPersistence`、`agents`/`sessions` 服务及其自有的受限 HTTP 路由）——不修改 DSH 核心文件。
- **删除文件归属校验**：文件必须列在会话的产出文件（`details.files`）中——`delete-file` 需要 `sessionId`，否则路径被拒绝（403），因此即使本地进程能访问回环 API，也无法删除工作区内任意文件。
